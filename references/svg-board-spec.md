# SVG 看板规范

本文件是 `SKILL.md` Step 4 的落地规范。目标：**一页纸、投屏可读、双击浏览器能开**。

起点永远是 [`../assets/board-template.svg`](../assets/board-template.svg)：复制一份，只替换 `<text>` 的文字与少量色值，**不改坐标网格**。改坐标一定翻车，改文字只要不超字数就安全。

## 二、字符预算（最容易翻车的地方）

**SVG 的 `<text>` 不会自动换行**：超出容器宽度就压到隔壁元素上，而且不报错。所以：

1. 每条 `<text>` 必须写 `data-max-width="<可用宽度>"`，给自检脚本用。
2. 手动按预算卡字数；超了就换行成第二条 `<text>`（基线 +行距），不是缩字号。

按「中文字符 = 1 个字号宽，ASCII ≈ 0.55 个字号宽」估算，模板各位置的安全字数：

| 位置 | 可用宽 | 字号 | 中文字数上限 |
|---|---|---|---|
| 标题 | 1120 | 30 | 37 |
| 副标题 | 1120 | 14 | 78 |
| 结论每条 | 1072 | 15 | 70 |
| 卡片标题 | 300 | 16 | 18 |
| 卡片要点 | 302 | 14 | 21 |
| 表头「事项」 | 530 | 13 | 40 |
| 负责人列 | 156 | 13 | 11 |
| 状态列 | 126 | 13 | 9 |
| 截止列 | 136 | 13 | 10 |
| 页脚 | 1120 | 12 | 91 |

折算示例：`固件 v0.9 卡在蓝牙丢包` ≈ 9 中文 + 5 ASCII ≈ 9 + 2.8 = 11.8 单位 ×14 ≈ 165px，占用 302 的一半，安全。

**只能放 3 条结论 / 每卡 5 条要点 / 最多 5 条待办**。超出的内容留在 Markdown 里，看板是索引不是全集。

## 四、结构与写法

### 根元素

```xml
<svg xmlns="http://www.w3.org/2000/svg" width="1200" height="880"
     viewBox="0 0 1200 880" role="img"
     font-family="-apple-system, 'PingFang SC', 'Microsoft YaHei', 'Noto Sans SC', sans-serif">
  <title>会议看板：{主题}</title>
  <desc>{一句话说明这张图是什么}</desc>
  …
</svg>
```

- `width` / `height` 必须与 `viewBox` 一致，否则某些浏览器按 1:1 缩小。
- 字体走系统栈，**不要** `@font-face` 引外部字体文件。
- 有 `<title>` / `<desc>` 的 SVG 贴到文档里更友好。

### 文本

```xml
<text x="122" y="685" font-size="13" fill="#1F2329" data-max-width="530">出首批 500 台排产计划表</text>
```

- 手动换行 = 再加一条 `<text>`，`y` 加行距。
- 需要整体加粗时用 `font-weight="700"`，不要用多个 `<tspan>` 拼。
- 需要混色时用 `<tspan fill="…">`，但**自检脚本按整条 text 计宽**，所以 `data-max-width` 按整条给。

### 转义

| 字符 | 写法 |
|---|---|
| `&` | `&amp;` |
| `<` | `&lt;` |
| `>` | `&gt;` |
| `"` | `&quot;`（在属性值里） |

中文全角标点（，。、：；！？「」）直接写，不需要转义。

### 禁止

| 禁止 | 原因 |
|---|---|
| `<image href="…">` / 外链图片 | 换机器就裂图，且违反"独立可开" |
| 外部字体、`<script>`、`<foreignObject>` | 浏览器安全策略会直接不渲染 |
| 绝对定位负坐标、超出 `viewBox` | 被裁切且不报错 |
| 用 `textLength` 硬压字距 | 中文会被压扁到读不出 |
| 深色背景 + 深灰字 | 投屏对比度不够 |
| 一屏塞 6 条以上待办 | 看板是索引，全量待办在 md 里 |

## 五、三种变体

按会议性质选一种，不要混：

1. **方案对比型**（默认）：三栏 = 决策 / 风险 / 下一步，底部待办条。
2. **推进流程型**：三栏 = 阶段一 / 阶段二 / 阶段三，卡片内改用 `① ② ③` 编号，待办条保留。
3. **多方关系型**：三栏 = 我方 / 对方 / 第三方，事件维度写各自诉求与承诺；待办条保留。

三种变体共用同一套坐标与页脚，**只换三栏的标题、内容与配色**。

## 六、自检

```bash
node scripts/check-board.mjs "2026-11-12_智能硬件项目推进会_看板.svg"
```

检查项：XML 合法性、`xmlns`/`viewBox`/`width`/`height` 齐全、`data-max-width` 文字溢出、元素越界、重复 `id`、外链与脚本。

退出码 0 = 通过。有 error 就改，别忽略；`warn` 允许人工判断后放行。

导出 PNG：浏览器打开 → 右键"图片另存为"，或开发者工具截图；不要为了导 PNG 引入额外依赖。
